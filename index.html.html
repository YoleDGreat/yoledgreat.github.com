Benefits of Using Mobile Apps

Convenience
A mobile app user can access and share information anytime or anywhere. Internet connection is not required on most apps.
Personalization
A user can change the settings of the mobile app based on his preferences. He can also receive notifications real time.
Productivity
Users can write, read, and present their reports using only their mobile phones. They can also manage their multimedia files and share to friends through social sites.

Development Environments (IDEs)

IDE (Integrated Development Environment)
A programming environment that has been packaged as an application program. Typically consists of a code editor, compiler, debugger, and a GUI builder.
Android Studio
The official IDE for Android application development, based on IntelliJ IDEA (a Java IDE).
Xcode
Allows users to build apps and run them directly on their Apple devices. Uses Swift, created by Apple for iOS, OS X, and watchOS development.
Xamarin
Extends the .NET developer platform with tools and libraries specifically for building cross-platform apps.
Corona
A free, cross-platform framework ideal for creating mobile apps and games. Uses Lua, an easy-to-learn scripting language.
Apache Cordova
An open-source mobile development framework that allows use of standard web technologies — HTML5, CSS3, and JavaScript for cross-platform development.

Challenges in Developing Mobile Apps

  • Understanding the market and the user – The current market scenario must be studied and the needs of the target users must be addressed.
  • Supporting multiple screen types – Devices come in different sizes and shapes, which affects how you design the screens and UI elements in your apps.
  • Maximizing app performance – The performance of an app is affected by factors such as battery life, multimedia content, and internet access.
  • Securing users – The users' data is the most valuable asset. Users' sensitive information must be protected at all times.
  • Remaining compatible with older versions – Not all users may have upgraded or may be able to upgrade their devices.

App Development Workflow

  • 1. Setup – Install and setup your chosen IDE. Create an emulator and connect hardware devices.
  • 2. Development – Write code, design a UI, and create resources for different device types.
  • 3. Building and Running – Build your project into a package that you can install and run on the emulator or an Android-powered device.
  • 4. Debugging, Profiling, and Testing – Continue writing your app but with a focus on eliminating bugs and optimizing app performance.
  • 5. Publishing – The app is configured and built for release and distributed to users.

App Components (App Fundamentals)

Activity
The entry point for interacting with the user. Represents a single screen with a user interface. Example: an activity that shows a list of new emails.
Service
Runs in the background to perform long-running operations or to perform work for remote processes. Example: playing music in the background while using a different app.
Broadcast Receiver
A component that enables the system to deliver events to the app outside of a regular user flow, allowing the app to respond to system-wide broadcast announcements. Example: a broadcast indicating that the battery is low.
Content Provider
Manages a shared set of app data that you can store which your app can access. Example: a content provider that manages the user's contact information.
Intent
A message defined by an Intent object that describes an action to perform, including the data to be acted upon, the category of component that should perform the action, and other instructions. App activities, services, and broadcast receivers are activated by intents.

Programming Languages for Android

  • C++ – Close to C# and Java, makes it easy for programmers to switch.
  • Swift – The official programming language for iOS.
  • Kotlin – Combines object-oriented and functional programming features. Uses val (never changes) and var (can change) keywords.
  • Java – Commonly used for Android development.
  • C# – Used especially with Xamarin.

The Manifest File (AndroidManifest.xml)

Manifest File
Details the components that exist in an app. The root element is <manifest>, and it must contain <application> as the last child element.
The manifest must declare: the app's package name, app components (<activity>, <service>, <receiver>, <provider>), required permissions, and hardware/software features.
<intent-filter>
Specifies the types of intents that an activity, service, or broadcast receiver can respond to.
<action> and <category>
<action> adds an action to an intent filter; <category> adds a category name to an intent filter.

Activity Lifecycle – Callback Methods

MethodDescription
onCreate()Invoked when the app is launched for the first time. Happens only once for the entire life of the activity.
onStart()Invoked before the activity becomes visible to the user. Followed by onResume() or onStop().
onResume()Invoked before the activity starts interacting with the user.
onPause()Invoked when the system is about to start resuming another activity. Followed by onResume() or onStop().
onStop()Invoked when the activity is no longer visible to the user. Followed by onRestart() or onDestroy().
onRestart()Invoked if the activity comes back after being stopped. Always followed by onStart().
onDestroy()Invoked when the activity is finishing or the system is temporarily destroying it (e.g., device rotation).
The parentActivityName attribute indicates that the main activity is the parent of a second activity, enabling a back-navigation arrow.

Activity Implementation

Main Activity (MainActivity.java)
Presented to the user when the app is launched. It can then start other activities to perform different actions.
Activity Life Cycle
The set of states an activity can be in during its entire lifetime.
Back Stack
Each time a new activity starts, the previous activity is stopped, but the system preserves the activity in a stack called the back stack.
To implement an activity: (1) Create an Activity Java class, (2) Implement a basic UI in an associated XML layout file, (3) Declare the new Activity in AndroidManifest.xml. In Android Studio, use File > New > Activity.

Intents

Intent
An asynchronous message used in an activity to request an action from another activity, or from some other app component. Can be used to start one activity from another and to pass data between activities.
Target Activity
The activity that will receive the intent.
Intent Data / Object
Contains a reference to the data you want the receiving activity to operate on.
Intent Extras
Carry information the receiving activity requires to accomplish the requested action (optional).
Intent Flags
May instruct the Android system how to launch an Activity or how to treat it after it's launched (optional).
Explicit Intent
The target of the intent (the class name of the activity) is already identified.
Implicit Intent
The target of the intent is not yet identified but there is a general action to perform. Also includes an action, category, and data type.

User Interface – Layouts

Layout
Defines the structure for an app's user interface. All elements are built using View (widget) and ViewGroup (layout).
View (Widget)
Draws something the user can see and interact with.
ViewGroup (Layout)
An invisible container that defines the layout structure for View and other ViewGroup objects.
Constraint Layout
Creates large and complex layouts with a flat view hierarchy (no nested view groups).
Linear Layout
Organizes its child view elements into a single horizontal or vertical row.
Relative Layout
Used to specify the location of child objects relative to each other or to the parent.
Web View
Used for displaying web pages.
Frame Layout
Designed to block out an area on the screen to display a single item.
Table Layout
Arranges its child objects into rows and columns.
Grid Layout
Arranges its child objects in a rectangular grid that can be scrolled.
wrap_content
Sets the size of the view to the dimensions required by its content.
match_parent
Sets the view to be as big as its parent view group will allow.
Context
An interface to global information about an application environment.

User Interface Components

Notification
A message that Android displays outside the app's UI to provide the user with reminders, communication from other people, or other timely information.
Notification Drawer
Allows to view more details and take actions with the notification.
App Bar / Action Bar
Provides a visual structure and interactive elements familiar to users. Comes with tabs or drop-down lists. Also known as the action bar.
Snackbar
Provides a quick pop-up message to the user.
Dialog
A small window that prompts the user to make a decision or enter additional information. It is not designed to fill the screen.
Menu
Used to present user actions and other options in the app's activities.
Toast
Provides simple feedback about an operation in a small popup. Automatically disappears after a few seconds.

Input Controls

Button
Usually a rectangle or rounded rectangle with a descriptive caption or icon in its center. Can have text, icon, or both. Has three states: normal, disabled, and pressed.
Raised Button
Appears lifted from the screen — the shading around it indicates that it is possible to tap or click it.
Flat Button (Borderless Button)
A text-only button that looks flat and doesn't have a shadow.
FAB (Floating Action Button)
A circular button that appears to float above the layout. F stands for Floating.
ImageView
Used to display image resources. Can be turned into a button by adding the android:onClick attribute in XML. Image files must be stored in res/drawable folder.
Input Controls
Interactive elements in the app's UI that accept data input.
EditText (Text Field)
Used for entering and modifying text.
CheckBox
Used for selecting one or more options (multiple selection).
Radio Button
Restricts the user to select only one (1) option from a set. Must be enclosed in a RadioGroup to ensure only one can be selected at a time.
Toggle Button
Lets the user change a setting between two (2) states. Multiple toggle buttons can exist in a layout.
Switch
A type of toggle button (for Android 4.0+) that provides a slider for selection.
Spinner
A drop-down menu for selecting only one (1) option. Has the android:entries attribute.
SeekBar
Dragged to the left or right to indicate a current progress level. Has the android:progress attribute.
Touch Gesture
Occurs when a user places one or more fingers on the touchscreen, and the app interprets that pattern as a particular gesture (tap, touch & hold, double-tap, fling, or scroll).

Image Formats & Drawables

Drawable
A graphic that can be drawn to the screen. The Drawable class is used for adding rich images in an app with minimal impact on performance.
  • WebP – A modern image format by Google for superior lossless and lossy compression. (Recommended)
  • PNG (Portable Network Graphics) – P stands for Portable. (Recommended)
  • JPG/JPEG (Joint Photographic Experts Group) – E stands for Experts. (Recommended)
  • GIF (Graphics Interchange Format) – I stands for Interchange. (Supported but NOT recommended)
  • BMP (Bitmap) – NOT recommended for use in Android Studio.
Image files should be saved in the app/src/main/res/drawable folder of the project.

Input Events

Event
Occurs when the user interacts with an input control or item in the user interface. Events can be generated using input controls.
Event Listener
An interface in the View class that contains a single callback method. Called when the View to which the listener has been registered is triggered by user interaction.
MethodInterfaceTrigger
onClick()OnClickListenerUser touches or focuses upon the item
onLongClick()OnLongClickListenerUser touches or focuses upon the item for a second
onKey()OnKeyListenerUser presses or releases a hardware key
onTouch()OnTouchListenerUser performs a touch event (press, release, or movement)

Styles and Themes

Style
A collection of attributes that define the look and format of a view.
Platform Styles
The styles that Android provides by default.
Theme
A collection of attributes that define the look and format of an activity or an entire app. Any style can be used as a theme.
Inheritance (Style)
Allows a style to inherit the properties of an existing style. To inherit a platform style: use the parent attribute. To inherit a custom style: use the parent style name as the prefix separated by a period.
  • A <style> element is created inside a <resources> element in any XML file in the values folder.
  • A <style> element includes: name, parent (optional), and any number of <item> child elements. Icon is NOT included.
  • To apply a platform style: @android:style/StyleName
  • To apply a custom style: @style/StyleName
  • The textColor attribute can accept hex values like #D7D6D7.
  • You can add as many <item> elements as needed to a <style> element.
  • To apply a theme to an activity: declare it inside an <activity> element in the manifest file.
  • To apply a theme to an app: declare it inside an <application> element in the manifest file.

Data Storage Options

Permanent Storage (Internal)
The getFilesDir() method returns the absolute path to the directory on the filesystem where the app's internal files are stored.
Shared Preferences
Allows you to save and retrieve primitive data types in key-value pairs. Used for storing small amounts of simple data.
Internal Storage
Store private data on the device memory. Files saved here are private by default and other apps cannot access them.
External Storage
Store public data on the shared external storage. Requires permissions (READ_EXTERNAL_STORAGE / WRITE_EXTERNAL_STORAGE).
SQLite Database
Store structured data in a private database. SQLite is a lightweight relational database included in Android.
Network Connection
Store data on the web with your own network server or use cloud services (e.g., Firebase).

File Storage Details

  • A file can be created in either of two directories: Permanent storage (internal) or External storage.
  • getFilesDir() – Returns absolute path to internal files directory.
  • getCacheDir() – Returns path to temporary/cache files directory.
  • getExternalFilesDir() – Returns path to external files directory.
  • Use FileOutputStream to write data to a file.
  • Use FileInputStream to read data from a file.
  • Use openFileOutput() to open or create a file in internal storage.

Shared Preferences

  • Use getSharedPreferences() to access a named preferences file.
  • Use getPreferences() to access a single preferences file for the Activity.
  • Use SharedPreferences.Editor to write to Shared Preferences.
  • Call apply() or commit() to save the changes.
  • Supports data types: int, float, long, boolean, String, Set<String>.

SQLite Database

SQLiteOpenHelper
A helper class used to manage database creation and version management.
SQLiteDatabase
The class used to manage and query a SQLite database.
  • onCreate() – Called when the database is created for the first time.
  • onUpgrade() – Called when the database needs to be upgraded.
  • getWritableDatabase() – Opens or creates a database for reading and writing.
  • getReadableDatabase() – Opens or creates a database for reading.
  • insert() – Inserts a row into a table.
  • query() – Queries a database and returns a Cursor.
  • update() – Updates rows in a table.
  • delete() – Deletes rows from a table.
  • Cursor – An interface that provides access to query result rows.
